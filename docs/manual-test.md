# 真机验证清单（0.1，M1–M6）

在 Mac 上，按顺序点一遍转录、翻译、转写、应用增强和词典，最后是 0.1 新增的首页、设置引导和设置各节（第 9 节）。自动测试（Linux 上的 Go 测试、CI 里 macOS 上的 Swift 测试）覆盖不了这些：权限、事件 tap、真实 App 的辅助功能、浏览器、真实的模型服务。

真机上不用人守着就能测的部分，已经由第 10 节的“自动真机测试（无界面）”覆盖：真实的辅助进程、录音链路（用文件代替麦克风）、阶跃和 DeepSeek 的完整会话、只读的辅助功能读取、Core Text 下的文字测量。**时间不够时，先跑第 10 节，再做第 10.4 节的“人工补测清单”（约 10 分钟）**，其余各节作为完整回归。

- **必做部分约 45 分钟**（第 9 节约 10 分钟）。标 **〔可选〕** 的步骤时间够再做，不影响结论。
- 每一步写了三件事：**做** / **应看到** / **不对时看**。
- 发现问题时，记下步骤编号和时间，导出诊断（设置 → 诊断与关于 → 复制诊断信息），并截图。日志不含密钥。

**排查时看这些地方**

| 名称 | 位置 |
|---|---|
| 日志面板 | Auralink 里按 ⇧⌘L |
| 日志文件 | `~/Library/Logs/Auralink/auralink.log`（app）、`helper.log`（辅助进程：热键、AX、粘贴、URL） |
| 历史详情 | 每次会话的原文、结果、交付方式、服务和模型、各阶段耗时、命中的规则 |
| 系统设置 | 隐私与安全 → 辅助功能 / 麦克风 / 自动化 |

## 0. 准备（约 5 分钟）

**0.1 构建产物**
- 已经打好的版本：`~/code/Auralink/build/darwin-arm64/Auralink.app`。
- 要重打时，在 Linux 上执行：`MAC_DIR=code/Auralink scripts/mac.sh 'scripts/build-helper.sh && go tool mygo build'`。
- 包是 ad-hoc 签名，每次重打以后，macOS 都会忘掉授权。

**0.2 Key 文件**：`~/.config/auralink-dev/keys.env`。app 本身不读这个文件，它只给第 8 节的自动测试用；建好以后，下一步往 app 里填 Key 也从这里复制。

```sh
# 有哪个写哪个，没有的行删掉
DOUBAO_APP_ID=...
DOUBAO_ACCESS_TOKEN=...
DASHSCOPE_API_KEY=...      # 阿里云百炼
OPENAI_API_KEY=...
STEPFUN_API_KEY=...        # 阶跃星辰（语音识别用 step-asr）
DEEPSEEK_API_KEY=...
```

执行一次 `chmod 600 ~/.config/auralink-dev/keys.env`，Mac 和 Linux 上各放一份。

**0.3 打开 app 并授权**
- **做**：
  1. 打开 `Auralink.app`。第一次打开（或者这台 Mac 上的数据里还没有记过“引导已完成”）会弹出**设置引导**：先点右上角 × 关掉它，第 9.2 节再完整走一遍。
  2. 进入设置（⌘,）→ 权限，授予辅助功能和麦克风。
  3. 如果系统设置里已经有一条旧的 Auralink 记录，而且它是打开的但不起作用，用 − 删掉，再重新添加。
- **应看到**：
  - 第 1 步弹出了设置引导；关掉以后再重启 app，不会再弹。
  - 权限页的两项都显示已授权。
  - 窗口底部没有状态栏；侧边栏底部“设置”右侧显示版本号，“设置”上方没有“辅助进程”的卡片（有就说明它没起来）。
- **不对时看**：`helper.log`，以及设置 → 诊断与关于。

**0.4 配置模型服务**
- **做**：
  1. 打开模型服务页，加一个语音识别服务（豆包或阿里百炼，有哪个用哪个），再加一个 DeepSeek 语言模型。
  2. 把 Key 填进去，各点一次“测试连接”。
- **应看到**：
  - 两项测试都通过。
  - 首页“还差 N 步”清单里的服务一项消失（全部就绪时整个清单不显示）；转录页顶部也不再提示还没有可用的服务。
- **不对时看**：卡片上的错误文字、日志面板、设置 → 网络（代理）。

**0.5 其他准备**
- 打开设置 → 隐私 → **保存录音**（第 7 节要用）。
- 先把这些 App 打开备用：TextEdit、备忘录、Chrome、Safari、Arc、Slack（或微信）、VS Code（或 Cursor）。

## 1. 转录（约 8 分钟）

热键默认值：转录 fn，翻译 fn⇧，转写 fn⌃，粘贴最近结果 ⌃⌘V；都是点按触发。

**1.1 基本流程**
- **做**：
  1. 在 TextEdit 里点一下，先复制一段别的文字，用来检查剪贴板会不会恢复。
  2. 按 fn，说一句中英混合的话，例如“今天下午三点开会，讨论 Auralink 的发布计划”，再按 fn。
- **应看到**：
  - 按下 fn 时响一声（Pop），浮窗出现在屏幕下方，不抢焦点：只有功能图标和波形（没有按钮、默认没有计时），说话时波形起伏，不说话时 bar 轻微地呼吸；流式服务的实时文字显示在下面。
  - 停止录音时再响一声（Tink）；按 Esc 取消时不响。
  - 停止后波形换成五个点的 loader（识别中、整理中），文字插入后浮窗很快淡出，不显示“已插入”。
  - 整理后的文字插在原来的光标处。
  - 按 ⌘V 粘出来的还是第 1 步复制的那段文字，说明剪贴板已经恢复。
- **不对时看**：
  - 浮窗没出现：`helper.log` 里有没有 hotkey 事件，权限页的辅助功能是否打开。
  - 没有插入：历史详情的“交付方式”。

**1.2 各种输入框**
- **做**：在备忘录、Slack、Chrome 网页里的 textarea、Chrome 里的富文本编辑器（Google Docs 或 Notion）里，各转录一次。
- **应看到**：每一处都直接插入，不会弹出答案卡片。contenteditable 的编辑器也一样。
- **不对时看**：历史详情的交付方式，和 `helper.log` 里 `textio.focus` 返回的 role。

**1.3 取消和停止**
- **做**：
  1. 录音时按 Esc。
  2. 再录一次，按住 fn 说话再松开（长按触发的快捷键）；或者再按一次 fn。
  3. 连续两次快速转录：第一次插入后马上再按 fn。
- **应看到**：
  - Esc 取消：什么都不插入，也不写历史，浮窗立刻消失。
  - 松开和再按一次都是停止。
  - 第二次的浮窗不会被第一次的淡出藏掉。

**1.4 浮窗外观（10-15 重做）**
- **做**：分别在白色网页（或 TextEdit）和深色窗口（终端、深色模式的编辑器）上方转录一次，录音时多停顿几秒。再在 设置 → 浮窗样式 打开“显示录音时长”录一次。
- **应看到**：
  - 浮窗是半透明的深色，背后的内容模糊地透出来；浅色和深色背景上图标、波形和文字都清楚。
  - 阴影很淡、四周完整，底部不被裁掉。
  - 圆角处模糊和深色底对齐，没有方形的边或缝。
  - 小胶囊里图标左边的留白和波形右边的留白一样宽，图标和波形上下居中对齐（和 Voxt 一样，148×48）。
  - 打开“显示录音时长”后，波形右边多一个计时，整行仍然居中。
  - 用流式服务（豆包或阿里）说一段长话：浮窗从小胶囊长高成“波形 + 一行文字”，只向上和两侧长大，底边和左右中心不动，不闪；宽度跟着文字走（文字两侧各留 20），最宽 300；文字超出后向左滚，始终显示最新的末尾，左边缘渐隐。用文件服务（阶跃）时，识别完、整理中也会这样显示原文。
  - 紧接着再按一次 fn：浮窗又是小胶囊（148×48），没有上一次的文字。
  - 录音时鼠标能点到浮窗下面的东西；出错提示上的 › 能点。
- **不对时看**：截图发回来（带背景）。自动的视觉回归见 10.5。
- **不对时看**：日志面板。

**1.4 目标不能输入**
- **做**：把焦点放在访达的文件列表或桌面上，然后转录。在弹出的答案卡片上点“复制”，再点“插入”。
- **应看到**：
  - 结果进入答案卡片：卡片和文字一样高，没有空白；没有橙色提示行，鼠标停在“插入”（笔）上时 tooltip 说明访达里没有可输入的位置。
  - 点“复制”后卡片不关，图标变成勾，约 2 秒后恢复。
  - 点“插入”时卡片先消失；插不进去时卡片回来，正文下面一行小字写着原因。
  - 点卡片上的按钮时，焦点不会被抢到卡片上。卡片不能拖动。
- **不对时看**：`helper.log` 的 focus 结果。

**1.5 中途切换 App**
- **做**：在 TextEdit 里开始录音，录音中切到备忘录，停止录音。然后切回 TextEdit，在卡片里点“插入”。
- **应看到**：
  - 结果进卡片（“插入”的 tooltip 说 TextEdit 已经不在前台）。
  - 切回 TextEdit 后点“插入”，文字插进 TextEdit。

**1.6 粘贴最近结果**
- **做**：按 ⌃⌘V。然后退出 Auralink（菜单栏 → 退出），重新打开，再按一次 ⌃⌘V。
- **应看到**：两次都粘出最近一次转录的结果。重启后的结果是从历史里读的。

**1.7 菜单栏**
- **做**：
  1. 在 TextEdit 里点一下，然后点菜单栏图标 →“开始转录”，说一句话，再点“停止转录”。
  2. 再打开菜单栏图标的菜单，把鼠标停在“最近结果”下面的第一条上，再点它，然后在 TextEdit 里按 ⌘V。
- **应看到**：
  - 开始后，菜单项变成“停止转录”；录音期间菜单栏图标变成“波形加一个实心圆点”，结束后恢复。
  - 文字插入 TextEdit，也就是点菜单之前在前台的 App。
  - 菜单里列出最近 3 条结果，每条只有一行短预览（约 13 个汉字或 26 个字母，末尾“…”），菜单不比“粘贴最近结果 ⌃⌘V”那一行宽多少；鼠标停住时 tooltip 显示全文；点一条会复制它的全文。
  - 菜单里还有“粘贴最近结果”“打开 Auralink”“设置…”“退出 Auralink”。

**1.8 试一试**
- **做**：在转录页的“试一试”点“开始”录一次；再在转录页直接按 fn 录一次（Auralink 在前台）。
- **应看到**：
  - 两次的结果、原文和各阶段耗时都显示在页面里，不会粘贴到 Auralink 自己的输入框。
  - 不弹浮窗，也不写历史。

**1.9 〔可选〕右 ⌘ 长按**
- **做**：在转录页把快捷键改成“右 ⌘、长按”。按住右 ⌘ 说话，松开，然后把快捷键改回 fn 点按。
- **应看到**：按下就开始录音，松开就停止。真机的右 ⌘ 以前没有测过。

## 2. 翻译（约 6 分钟）

**2.1 选中文字的翻译**
- **做**：在 TextEdit 里选中一段英文，按 fn⇧。
- **应看到**：
  - 浮窗显示“正在翻译选中的文字…”和流式草稿。
  - 不录音：菜单栏不出现麦克风的橙点。
  - 译文替换选中的文字，剪贴板恢复。
- **不对时看**：`helper.log` 里 `textio.selection` 的结果（AX 读到的，还是 ⌘C 读到的）。

**2.2 网页上的选区：进卡片，在卡片里换语言**
- **做**：
  1. 在 Safari 的网页正文里选中一段文字，按 fn⇧。
  2. 点卡片标题行右侧的语言胶囊（“简体中文 ⌄”），在弹出的下拉（我们自己的样式，在卡片上方）里选“日语”。
  3. 在 Chrome 里重复一遍。
- **应看到**：
  - 网页上的文字不能编辑：翻译过程中浮窗是胶囊，下面一行先显示选中的原文，再显示译文草稿（和转录的胶囊一样宽、一样单行滚动）；完成后一次切成卡片（宽 440），底边不动、不闪，不会粘到别处。
  - 换成日语后：原来的译文留着，标题旁转一个小 spinner，胶囊已经显示“日语”；译好后正文换成日文。不录音，也不会插入到网页里。
  - **重点**：下拉是独立的不激活浮窗，看它能不能正常弹出、滚动、选择；选完前台 App 还是浏览器，卡片位置不动。再点一次胶囊、按 Esc、切到别的 App，下拉都会收起（Esc 先收起下拉，再按一次才关卡片）。
- **不对时看**：截图卡片；日志面板。

**2.3 其他 App 里的选区**
- **做**：在 Chrome 的 textarea、备忘录、Slack 里各选一段文字，做一次翻译。
- **应看到**：选中的文字能读到，并且被译文替换。

**2.4 编辑器：没有选区时不能把整行当成选区**
- **做**：在 VS Code 或 Cursor 里不选任何文字，按 fn⇧。再选中一段文字，按 fn⇧。
- **应看到**：
  - 没有选区时，直接开始录音，不会把光标所在的整行当成选区。这类编辑器不模拟 ⌘C。
  - 有选区时，AX 能读到选中的文字。
- **不对时看**：`helper.log` 的 selection。

**2.5 语音翻译**
- **做**：
  1. 不选文字，按 fn⇧，说一句中文，再按 fn⇧。
  2. 在翻译页打开“在卡片中显示结果”，再做一次。
  3. 把这个开关关回去。
- **应看到**：
  - 第一次：英文译文插入光标处。
  - 第二次：结果进卡片。

**2.6 〔可选〕读选区慢的 App**
- **做**：在微信里不选文字，按 fn⇧，按下以后马上开始说话。
- **应看到**：最多 1.5 秒后开始录音，开头说的话没有丢。

## 3. 转写（约 4 分钟）

**3.1 改写选中的文字**
- **做**：在 TextEdit（或邮件）里选中一段话，按 fn⌃，说“改得正式一点”，再按 fn⌃。然后在卡片上点“插入”（笔）。
- **应看到**：结果进卡片（同 Voxt，标题“AI 回答”，有“继续”），不会自动替换；点“插入”后卡片消失，结果替换选区。

**3.2 按指令生成，再继续追问**
- **做**：
  1. 不选文字，按 fn⌃，说“写一段两百字的自我介绍”，再按 fn⌃。
  2. 卡片出现以后，再按 fn⌃（或点卡片上的“继续”），说“短一点”，再按 fn⌃（或点“完成”）。
  3. 再追问一次，录音时按 Esc；再按一次 Esc。
- **应看到**：
  - 生成过程中，浮窗还是胶囊，下面一行先显示指令，再显示回答草稿（宽度规则和转录一样，最宽 300）；完成后一次切成卡片（宽 440），底边不动、不闪。不管回答长短都进卡片（10-15 之前短回答会直接插入），卡片标题是回答的标题，标题行有“继续”。追问的回答是纯文本，没有标题。
  - 追问时卡片不消失，变成对话：标题位置是会动的小波形，正文是气泡（右边“你”，左边回答），识别的文字和新回答都流式出现，自动滚到最新。
  - 鼠标移到回答气泡上，右上角出现“复制”。
  - 录音时按 Esc：只取消这次追问，卡片留着；第二次 Esc 关闭卡片。

## 4. 应用增强（约 8 分钟）

**4.1 没有自动化权限**
- **做**：打开系统设置 → 隐私与安全 → 自动化。
- **应看到**：
  - 列表里没有 Auralink。
  - 整个验证过程中，都不应该弹出“想要控制 Safari/Chrome”的对话框。

**4.2 按网址和浏览器匹配**
- **做**：
  1. 在应用增强页新建分组 A，网站规则写 `github.com`。
  2. 新建分组 B，成员选 Chrome，插入后按键选“无”。
  3. 在 Chrome、Safari、Arc 里，各开一个 github.com 标签和一个别的网站的标签。
  4. 在每个标签页面里的输入框（例如 github 的搜索框或评论框）按 fn，说一句话。
- **应看到**：
  - 浮窗的标签、历史详情的“规则”和网址，与当前标签一致：
    - github.com 的标签命中分组 A（显示“github.com · A”）；
    - Chrome 里别的网站命中分组 B（按浏览器）。
  - **请记下每种浏览器有没有读到网址**：
    - Safari 在前台时能不能读到，是重点；
    - Arc 分屏时，读到的是不是正在输入的那一边。
- **不对时看**：`helper.log` 里 `browser.url` 的 `via`（ax-focus / ax-document / ax-weburl / none）和耗时。

**4.3 预览和浏览器对话框**
- **做**：
  1. 回到 Auralink 的应用增强页，看顶部的预览，点“重新读取”。
  2. 点“把 github.com 加入 …”。
  3. 点页头右上角的地球图标，打开“浏览器”对话框。
- **应看到**：
  - 预览显示上一个前台 App 和它的网址。
  - Safari 在后台时，预览显示“没有网址…”的说明。
  - 加入后，网站规则生效。
  - 浏览器对话框里，刚用过的浏览器标着“读到了网址”或“读不到网址：只能按应用匹配”。

**4.4 插入后按键**
- **做**：
  1. 新建分组“聊天”，成员选 Slack（或微信），插入后按键选 ↩。
  2. 在 Slack 的一个测试频道或自己的私信里转录一句话。
  3. 把焦点放在 Slack 里不能输入的地方再转录，在答案卡片上点“插入”。
- **应看到**：
  - 第 2 步：插入后自动发送。
  - 第 3 步：结果进卡片，点“插入”后不会自动发送。
- **不对时看**：历史详情的规则，以及 `helper.log` 的 paste 参数（press）。

**4.5 按键的作用范围**

## 10. 自动真机测试（无界面）

在一台正在被别人用的 Mac 上也能跑（例如 AudioSmith 同时在跑测试）。从 Linux 通过 ssh 执行，全程：

- 不开窗口，不改变前台 App，不抢焦点；
- 不发按键，不装事件 tap（只调用 `hotkey.status`，不调用 `hotkey.configure`）；
- 不碰剪贴板，不做真实粘贴（文本输入输出是只记录文字的假实现，只读调用真实的 `textio.focus`）；
- 不用麦克风，也不会弹出授权窗口：辅助进程的录音改成读取 WAV 文件（`AURALINK_HELPER_CAPTURE_FILE`，**仅用于测试**，见 [helper-protocol.md](helper-protocol.md) 第 4 节）。读出来的音频和麦克风走同一条链路：混成单声道、重采样、`PCMFramer`、`capture.level` 和 `capture.pcm` 通知、停止、取消和 maxSeconds 的结束方式都一样；
- 只读取已经在运行的浏览器的网址（按 pid），不启动、不激活浏览器；
- 占用资源少：`nice -n 10`，Swift 和 Go 都只用 2 个并行任务（`GOMAXPROCS=2`、`GOFLAGS=-p=2`），各步骤依次执行；每一步开始前检查空闲内存，低于 40%（`AURALINK_MIN_FREE`）就停止；结束时确认没有残留的辅助进程。

**10.1 怎么跑**

```sh
# 在 Linux 上执行。同步到独立目录（不要用 code/Auralink，那是给人用的构建）
MAC_DIR=code/Auralink-mt scripts/mac.sh scripts/mac-e2e.sh --offline   # 不调用真实服务
MAC_DIR=code/Auralink-mt scripts/mac.sh scripts/mac-e2e.sh             # 再加真实服务：阶跃 1 次，DeepSeek 3 次
```

真实服务的 Key 从 Mac 上的环境变量或 `~/.config/auralink-dev/keys.env` 读取，缺哪个就跳过对应的测试。如果不想在 Mac 上放 Key 文件，可以从 Linux 通过 stdin 传过去（Key 不落盘，也不出现在命令行参数里；测试日志只打印长度和耗时）：

```sh
MAC_DIR=code/Auralink-mt scripts/mac.sh   # 只同步
grep -E '^(STEPFUN_API_KEY|DEEPSEEK_API_KEY)=' ~/.config/auralink-dev/keys.env | \
  ssh mac-air 'cd code/Auralink-mt && set -a && . /dev/stdin && set +a &&
    export PATH=/opt/homebrew/bin:$PATH GOTOOLCHAIN=auto GOPROXY=https://goproxy.cn,direct && scripts/mac-e2e.sh'
```

单独跑某一项：`AURALINK_MAC_E2E=1 AURALINK_HELPER=<辅助进程路径> go test -run 'TestMacHelperReadOnly' -v .`（在 Mac 上执行；辅助进程用 `scripts/build-helper.sh --out DIR` 编译）。

**10.2 覆盖了什么**（`mac_e2e_test.go`、`helper/Tests/AuralinkHelperKitTests/CaptureFileTests.swift`）

**10.3 发现的问题**

- **Arc 的 `browser.url` 读不到网址**（`via none`，查满 400 个节点，641 ms），同一时刻 `textio.focus` 也报“没有焦点元素”。M5 当时在 Arc 上走 `ax-focus` 读到了（49 ms）。原因：Chromium 只在辅助功能客户端请求时才构建网页的 AX 树，辅助进程原来只给 Electron 应用设置 `AXManualAccessibility`。**已修复（#12）**：Go 用 `app.configure` 下发 Chromium 系浏览器名单，辅助进程在它们切到前台时设置这个属性（每个进程一次）；`browser.url` 查不到网页区域时也设置一次，150 ms 后重读（结果带 `retried`）。10-15 在 mac-air 上按 pid 实测：Arc 从 `none` 变成 `ax-focus`，属性设置后一直有效（新的辅助进程第一次读 20–40 ms，之后 2–5 ms）；Chrome 没有退化。切到前台时设置这一条没法在无界面测试里触发，留给人工补测第 5 步。

**10.5 浮窗的视觉回归（约 1 分钟，有短暂的浮窗）**

`scripts/mac-overlay-check.sh` 让真正的浮窗窗口依次走过各个状态，每一步截图并记录窗口的 frame。它不是无界面的：浮窗和它下面的一块背景板会在屏幕底部（浮窗平常的位置，鼠标所在的显示器）出现约 15 秒，每个状态约 1 秒；但两者都是不激活的面板，不抢焦点、不改前台 App，也不碰剪贴板和按键。

```sh
# 在 Linux 上执行。同步到独立目录（不要用 code/Auralink）
MAC_DIR=code/Auralink-ov scripts/mac.sh scripts/mac-overlay-check.sh
MAC_DIR=code/Auralink-ov scripts/mac.sh --pull build/overlay-check     # 把结果拿回来
```
